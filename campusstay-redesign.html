01 — Vision
What CampusStay TZ becomes

CampusStay TZ is Tanzania's trust-first student housing marketplace. It connects verified landlords, dalalis, and property managers with students and other tenants who need safe, affordable accommodation near universities in Dar es Salaam and beyond.

The redesign is not cosmetic. It rebuilds the product from the data model up — replacing the Spring Boot backend with Supabase for realtime, auth, storage, and Postgres in one unified platform — while designing every screen for a mobile-first audience that primarily uses 4G on Android devices.

The core promise: every listing is verified. Every landlord is accountable. Every student is protected.

03 — Feature Set
Every feature, phased
🔐 Authentication & Verification
V1 Core
Supabase Auth handles email/password registration. Phone OTP verification via Africa's Talking or Supabase SMS. ID/passport upload + selfie stored in Supabase Storage. Admin manually reviews identity docs before landlord activation.
  • Email + password registration with email confirmation link
  • Phone number OTP verification (required for landlords, optional for tenants)
  • National ID / Passport document upload (Supabase Storage, private bucket)
  • Selfie upload for liveness check
  • Role selection at registration (student/tenant vs. lister)
  • Lister sub-role: Property Owner, Property Manager, or Dalali
  • Persistent sessions with Supabase JWT refresh tokens
  • Logout all devices
🔍 Listing Search & Discovery
V1 Core
The home screen is a powerful search experience. Tenants filter by location, price, gender preference, amenities, and university proximity. Results show on a card list and optionally a map.
  • Full-text search on listing title, description, ward, district
  • Filter by: price range, gender preference (male/female/mixed), room type, utilities included
  • Filter by university proximity (UDSM, Ardhi, MUHAS, IFM, Makumira)
  • Sort by: newest, price low-to-high, highest rated, featured
  • Map view with pins using Leaflet.js + OpenStreetMap (free, no API key)
  • Infinite scroll on card list
  • Verified badge on approved listings
  • Availability status chip: Available / Occupied / Coming Soon
📋 Listing Detail Page
V1 Core
Rich room detail view with scrollable photo gallery, structured metadata sections, and a sticky CTA for inquiry or booking.
  • Scrollable photo gallery (bedroom, kitchen, bathroom, outside)
  • Overview: price, room type, available from, gender preference
  • Amenities checklist: WiFi, water, electricity, generator, security, parking
  • Location section: ward/district/street + embedded map pin
  • House rules section
  • Landlord profile card: name, verified badge, member since, response rate
  • Reviews section with star ratings
  • Sticky bottom bar: Save ♥ · Inquire · Book (phase-gated)
  • Share button (native share sheet on mobile)
📝 Listing Wizard (Lister)
V1 Core
Redesigned 5-step wizard with auto-save, validation, and AI photo checks. Each step is a dedicated screen on mobile.
  • Step 1 — Identity: Legal name, phone OTP, profile photo, ID/selfie upload
  • Step 2 — Property Basics: Title, description, room type, gender preference, availability date
  • Step 3 — Location & Price: Region → District → Ward → Street dropdowns, map pin capture, monthly price, utilities included toggle, payout bank setup
  • Step 4 — Amenities & Rules: Checklist (WiFi, water, electricity, security, parking, generator) + house rules free text
  • Step 5 — Photos & Review: Upload 4 required angles (bedroom, kitchen, bathroom, outside), AI angle verification, mandatory policy acceptance, submit
  • Auto-save draft to Supabase (not localStorage) so it persists across devices
  • Blocking reason shown inline before submit button
  • Submission creates listing in PENDING status
💬 Inquiry & In-App Chat
V1 Core
Tenants can send a structured inquiry from a listing page, which opens a chat thread with the landlord. Realtime via Supabase Realtime.
  • Inquiry form: name (pre-filled), move-in date, message, contact preference
  • Inquiry creates a conversation thread between tenant and landlord
  • Realtime chat powered by Supabase Realtime subscriptions
  • Message seen/delivered status
  • Landlord can mark inquiry as: Interested / Not Available / Booked
  • In-app notification badge for unread messages
  • Chat list screen showing all active conversations
  • No external contact details shared until both parties consent
❤️ Saved Favourites
V1 Core
Tenants can save listings to revisit later. Saved listings are synced to Supabase and available on any device.
  • Heart button on listing card and detail page
  • Saved listings tab in tenant profile
  • Notification if a saved listing becomes unavailable or gets a price change
📊 Landlord Dashboard
V1 Core
The landlord's home base. Shows listing status, inquiries, and basic performance data.
  • Listing status cards: Pending / Approved / Rejected (with reason) / Flagged
  • View count and inquiry count per listing
  • Unread message badge
  • Quick actions: Edit listing, Mark as occupied, Relist
  • Verification status indicator with next steps
  • Rejection reason displayed clearly so landlord can fix and resubmit
🛡️ Admin Panel
V1 Core
Rebuilt admin panel with bulk actions, rejection reason templates, and a full audit trail.
  • Dashboard: total listings, pending queue count, flagged count, new signups today
  • Landlord queue: view ID docs, selfie, profile — Approve / Reject / Suspend with reason
  • Listing queue: view full listing + photos — Approve / Reject / Flag / Unflag
  • Bulk approve / bulk reject with shared reason
  • Rejection reason templates (pre-written, selectable)
  • Full audit log: who did what, when, on which entity
  • Search/filter landlords and listings by status, date, university
⭐ Reviews & Ratings
V2
After a confirmed stay or booking, tenants can rate the property and landlord. Reviews are the platform's long-term trust signal.
  • Star rating (1–5) + written review
  • Dimensions: Accuracy, Cleanliness, Communication, Location, Value
  • Landlord can leave a reply
  • Admin can remove inappropriate reviews
  • Aggregate rating shown on listing card and detail page
📅 Booking & Availability
V2
Tenants can request a booking for a specific move-in date. Landlords confirm or decline. No payment processing in V2 — intent only.
  • Available from date on each listing
  • Vacancy status: Available / Occupied / Coming Soon
  • Booking request form: move-in date, duration, message
  • Landlord confirms or declines within 48 hours
  • Confirmed booking marks listing as Occupied
💳 Rent Payment Tracking
V3
Track monthly rent payments within the platform. M-Pesa and Tigopesa integration for Tanzania-native mobile money.
  • Payment schedule per active booking
  • M-Pesa / Tigopesa STK push integration
  • Payment receipt stored in Supabase
  • Landlord payout dashboard
  • Commission tracking for dalali accounts
📈 Monetization Tiers
V3
Subscription plans for landlords. Free tier allows 1 listing. Verified tier unlocks more listings and badge. Premium tier adds featured placement.
  • Free: 1 listing, basic badge
  • Verified (TZS 15,000/mo): up to 5 listings, verified badge, analytics
  • Premium (TZS 35,000/mo): unlimited listings, featured placement, priority review
  • Dalali commission tracking (% per confirmed booking)

06 — Tech Stack
Supabase + React, chosen deliberately
Auth
Supabase Auth
Email/password + OTP SMS. JWT refresh tokens. RLS integration. No separate auth server needed.
Database
Supabase Postgres
Managed Postgres with RLS policies. Replaces Spring Boot + Flyway. Schema migrations via Supabase CLI.
Realtime
Supabase Realtime
Chat subscriptions and live notification badges with zero additional infrastructure.
File Storage
Supabase Storage
Public bucket for listing photos (CDN-served). Private bucket for ID docs and selfies. Replaces local disk/DB blob storage.
Frontend
React + Vite
Existing team familiarity. Fast HMR dev experience. Tailwind CSS for styling.
Routing
React Router v6
Nested routes for role-protected areas (landlord, admin). Lazy loading per route.
State
Zustand
Lightweight global state for auth user, unread message count, saved listings. No Redux boilerplate.
Map
Leaflet.js + OSM
Free, no API key. OpenStreetMap tiles. Good Tanzania coverage. Works on low-bandwidth connections.
AI Photo Check
OpenAI Vision API
Called from a Supabase Edge Function on listing submission. Keeps API key server-side.
Backend Logic
Supabase Edge Functions
Deno-based serverless functions for: OTP verification, AI photo check, view count increment, notification triggers. Replaces Spring Boot.
SMS / OTP
Africa's Talking
Tanzania-native SMS gateway. Cheapest per-SMS rate for TZ. Supabase Auth custom SMS hook.
Deployment
Vercel (frontend)
Zero-config React deployment. Free tier sufficient for early scale. Backend is fully Supabase — no Docker needed.
07 — API Design
Supabase client + Edge Functions

Most data access happens through the Supabase JS client directly (with RLS enforcing access control). Edge Functions handle operations that require server-side logic or secret API keys.

Supabase Edge Functions

POST /functions/v1/verify-phone-otp Sends OTP via Africa's Talking, verifies code, updates profiles.phone_verified
POST /functions/v1/inspect-photo Accepts image URL + expected angle, calls OpenAI Vision, returns {pass, confidence, reason}
POST /functions/v1/submit-listing Validates all required fields + AI photo results, creates listing row in PENDING status
POST /functions/v1/increment-view Atomically increments listings.view_count for a given listing ID (prevents client-side manipulation)
POST /functions/v1/admin-action Handles approve/reject/flag/suspend with audit log entry. Admin JWT required.

Key Supabase Client Queries (RLS-protected)

GET listings (status=approved) Public search. RLS: anyone can read approved listings. Filters applied client-side via query params.
GET listings (lister_id=me) Landlord's own listings. RLS: lister can read all their own listings regardless of status.
GET conversations + messages RLS: only tenant_id or lister_id of the conversation can read messages.
GET profiles (admin only) RLS: role=admin can read all profiles. Others can only read their own.
POST saved_listings Insert/delete. RLS: tenant can only insert rows where tenant_id = their own auth.uid().

10 — Migration Note
Moving from Spring Boot

The existing Spring Boot backend can be retired incrementally. Start by standing up the Supabase project and migrating the database schema with equivalent Postgres tables and RLS policies. Port the AI photo check endpoint to a Supabase Edge Function first — this is the only truly custom server-side logic. The admin action endpoints follow. Auth migrates automatically since Supabase handles it natively. Once the Edge Functions cover all custom logic, the frontend can be pointed at Supabase directly and the Spring Boot container retired.

Existing listing data and user accounts can be exported from Postgres and imported into Supabase using pg_dump / psql. ID documents should be re-uploaded to Supabase Storage private buckets, or migrated by copying files from the old volume.

Docker Compose is no longer needed in the new architecture — development uses the Supabase CLI (supabase start) which spins up a local Supabase stack, and production is the hosted Supabase project.
